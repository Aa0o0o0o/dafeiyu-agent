# 恢复与部署所需条件

此仓库用于保存源代码与架构。它没有提供生产环境、账号状态、模型权重、原始聊天或密钥；不要把它当成可直接恢复原机全部体验的完整镜像。

1. 使用隔离项目目录和独立 QQ 账号，明确要开放的好友、群、浏览器、语音、微信和自主分享范围。QQ 登录和第三方验证由账号持有人完成。
2. `config/versions.json` 记录原部署的 AstrBot、NapCat、QQ 和 Python 版本，锁文件与其他 manifest 记录对应依赖、散列及部分兼容性细节。下载并按第三方许可安装依赖。原来的 `vendor/`、项目虚拟环境、浏览器、语音环境和模型权重未包含在仓库中；外部依赖及其定制补丁需要在目标环境重新核验，不能假设上游任意版本兼容。
3. 复制 `config/settings.example.json` 至本机 `config/settings.json` 后填写并检查真实账号和权限。示例中账号为空，自动自主探索、主动分享、语音和广泛好友/群启用已关闭。该文件由 `.gitignore` 排除，不能提交真实配置。
4. 部分旧实现仍在代码中检查固定身份或用固定参数启动 QQ，而不是统一从配置读取。搜索 `1111111111`、`2222222222`、`3333333333`，逐处理解身份、授权和作用域语义后再配置；不能直接将这些示例值视为有效账号，不能单纯删除这些校验。涉及微信单会话的强约束尤其需要重新设计并用合成数据测试。
5. 通过 `scripts/setup_local.py` 在本机交互输入 DeepSeek 凭据，确认密钥及 OneBot token 仅在受保护的本地配置中保存。Windows DPAPI 数据通常与原 Windows 用户环境绑定；仓库不含这些数据，也不能替代迁移。
6. 用隔离虚拟环境、合成账号/消息和假模型运行 `python -m unittest discover -s tests` 等检查。部分测试依赖缺失的 AstrBot / 平台组件或其他可选环境；先按失败原因补依赖并记录范围，不能把跳过或导入失败写成通过。先验证入站认证、登录身份、允许列表/真实好友群、会话隔离、删除传播和真实回执，再连接授权的服务。

语音需要单独核验引擎版本、GPU/依赖、授权参考音频、声音注册及使用许可；空仓库不会恢复原有音色。浏览器需要隔离运行时，不能使用用户私人浏览器登录态。微信导入、自动探索和主人消息分享都应重新核对当前授权与配置，任何历史描述不自动构成新环境的授权。
